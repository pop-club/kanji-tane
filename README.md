# かんじのたね（旧名 Pop-Kanji）

小学生が手書きで答える漢字テスト。まちがえた字は「にがてリスト」に入り、練習プリントを印刷できる。通信なしで端末の中だけで動く。

## STEP 1 手書き認識 技術検証

## 学習アプリ（STEP 2〜3、小1から）

- 画面: ホーム／学年えらび／テスト（手書き）／結果／にがてリスト／練習プリント／学習データ／このアプリについて
- 問題: 読みがな付きの熟語・短い文の、1字を空欄にした形。小1は80字・240問（熟語144・文96）
  - 熟語は JMdict（EDRDG, CC BY-SA 4.0）の共通語から選定、文は Pop-Kanji で作成（data/src/g1.txt）
  - tools/build_questions.py で検査: 空欄の字・使う漢字の学年・JMdict の収録と読み・同じ読みで別の字が入らないか
- 判定: 1位なら正解／迷ったら書き直し（3回まで、まちがいにしない）／それ以外はまちがい
  「ただしく かいたのに まちがいに なった」で、まちがいとして記録しない
- 習得: はじめて正解=おぼえかけ／まちがい=にがて／2回つづけて正解=おぼえた（7日後に再確認）／再確認でまちがい=にがて
- 保存: IndexedDB（この端末だけ）。JSON で書き出し・読み込み
- 練習プリント: A4・1ページ10問・7マス（1マスめにうすい手本）・こたえのページ付き。ブラウザの印刷を使う

## 動かし方

```
./build.sh
cd build && python3 -m http.server 8000
```
同じWi-Fiのタブレットで `http://<PCのIPアドレス>:8000/` を開く。
`file://` で直接開くとブラウザによっては動かないため、簡易サーバー経由で開くこと。

## 判定ルール（js/recognizer.js の judge）

| 判定 | 条件 | 記録 |
|---|---|---|
| 正解 | 1位が出題漢字 | 正解 |
| もう一度書いてね | 出題漢字が10位以内にあり、距離が1位の1.25倍以内 | 不正解にしない |
| 不正解 | それ以外 | 不正解（「〇〇に見えた」を表示） |

距離には画数の差を1画につき10%上乗せする（間→問のように、1画少ない似た字に1位を取られるのを防ぐ。tools/penalty_test.js で決定）。

「上位5位以内なら正解」は採用しない。士を書くと土が100%上位5位に入り、書き間違いを正解にしてしまうため。

## 参照パターンの不備（要修正）

正しい画数と手本の画数がずれている字（小1〜小6、17字）。
大きくずれている「衛（16画→手本12画）」「臨（18画→手本6画）」は、正しく書いても認識できない。

数 歌 社 馬 鳥 鳴 島 進 駅 健 散 験 慣 衛 敬 熟 臨

## 実際の手書きでの検証（2026-11-10、Windows PC・マウス、34回）

正解26・書き直し5・不正解3（画数差の上乗せ後）。
正しく書いたのに不正解：衛（手本の不具合）、王（→工）、右（→石）。
王・右・玉は手本1つでは足りないため、手書きの手本を追加する必要がある。

## 手本の登録（検証ページの「手本を登録」タブ）

- 正しい画数で書いたときだけ登録できる（画数は js/stroke-counts.js で確認）
- 登録した手本はその端末に保存され、すぐ判定に使われる（「登録した手本を判定に使う」で切り替え可）
- 衛・臨・熟は元の手本が壊れているため、登録した手本があれば元の手本を使わない
- 「記録と手本をコピー」した内容を `node tools/import_samples.js <ファイル>` で取り込むと、アプリに同梱される
- 手本はアプリ利用者本人の手書きなので、第三者のライセンスは関係しない

## 本人の手書きを手本にした効果（2026-11-11、PC・マウス 2回分）

ある回の記録を手本にして、別の回を判定した（標準画数どおりの記録のみ使用）。

| | 手本なし | 本人の手本あり |
|---|---|---|
| 1回目を手本→2回目を判定 | 正解22・書き直し5・不正解2 | 正解27・書き直し1・不正解1（衛のみ） |
| 2回目を手本→1回目を判定 | 正解24・書き直し4・不正解2 | 正解29・書き直し1・不正解0 |

登録した手本は**同じ画数の入力とだけ比べる**。画数を問わず比べると、王4画の手本が玉5画を、大3画の手本が犬4画を引き寄せ、
不正解が増えた（玉→王、犬→大、力→大）。同じ画数に限ると、似た字の取り違えは増えず（2.4%→2.1%）、
正しく書いた似た字の正解率は 93.1%→98.3% に上がった。

2回とも誤認識した字：右→石、午→牛。新しく出た誤認識：日→田（横長に書いた日）。

## KanjiVG から作った手本（2026-11-11 採用）

手書きの手本は人によって癖が違うため、1人分の登録では一般化しにくい。そこで KanjiVG の筆画データから、
1字につき「元の形1つ＋形を少し崩した4つ」の手本を、小1〜小6の1026字すべてに作った（5130件、約3.3MB）。
手本は同じ画数の入力とだけ比べる。元の手本（KanjiCanvas）は、画数が違う17字だけ使わず、それ以外は残す
（画をつなげて書いた字を拾うため）。

実際の手書き記録（PC・マウス 2回 66件）での評価。合成データは KanjiVG 由来なので評価に使わない。

| | 手本なし | KanjiVG手本あり（1字5つ、乱数3通りの平均） |
|---|---|---|
| 画数どおりに書いた59件 | 正解46・書き直し9・不正解4 | 正解55.3・書き直し3.3・不正解0.3 |
| 似た字の答えとして判定（取り違えて正解にした件数） | 7 / 66 | 3 / 66（うち1件は本当に「玉」を書いた記録） |

1字3つより5つのほうが平均で少し良い（正解54.3→55.3、不正解1.3→0.3）。認識時間は1字20ms前後。

## 全学年の問題（2026-11-11）

| 学年 | 字数 | 問題数 |
|---|---|---|
| 小1 | 80 | 240 |
| 小2 | 160 | 480 |
| 小3 | 200 | 600 |
| 小4 | 202 | 606 |
| 小5 | 193 | 579 |
| 小6 | 191 | 573 |
| 合計 | 1026 | 3078 |

- 元データは data/src/g<学年>.txt。tools/build_questions.py の検査を全学年で通過
- 小2以降の文と意味の説明は、前の学年までに習った漢字をふりがな付きで使う（tools/kanjify.py）
- 熟語の空欄に別の字が入ってしまう問題は差し替え、文の意味で答えが決まるものは ※ で確認済みにした
- まちがえた字は「おてほんを みて もういちど かく」で、うすいお手本をなぞって練習できる（記録はまちがいのまま）

## テストの再出題・途中保存・スマホ操作（2026-11-11）

- 学年のテストは、4問に1問くらい（5問→1・10問→3・20問→5）にがて・再確認の字をまぜる。のこりは まだ出ていない字から
- テストでまちがえた字（「よみとれず」はのぞく）は、さいごに別の問題でもう一度出す。答えを見た直後なので記録は変えない
  （にがてから外れるのは、別のテストで2回つづけて正解したとき）
- 1問ごとに学習記録とテストの記録を保存する。「やめる」と、答えたところまで（「つぎへ」を押す前の問題もふくむ）を保存して結果を出す
- 書く枠の左上に「いま書いた画数 / その字の画数」を出す（ちょうどで緑、多すぎると黄色）
- スマホ縦向き：テスト中はヘッダーを隠し、問題・枠・ボタンが1画面に入るように枠の大きさを合わせる（js/app.js fitPad）。答えたあとの「つぎへ」は画面下に固定
- スマホ横向き：左に問題、右に枠とボタンを縦にならべる
- ボタンを続けてタップしても画面が拡大しない（touch-action: manipulation）
- ホームの「おぼえぐあい」の数字は、せいかいした字（おぼえた＋おぼえかけ）。下に おぼえた・おぼえかけ・にがて の内わけを出す

## 更新（バージョンアップ）したとき

- build.sh が日時からバージョン（例 2026.11.11-2040）を作り、js の URL に `?v=バージョン` を付ける。新しいバージョンを公開すると、ブラウザは新しい js を読む
- 「このアプリについて」に、いまのバージョンと「あたらしい バージョンを よみこむ」ボタン（ページを取りなおして開きなおす）。学習の記録（IndexedDB）は消えない
- GitHub Pages はページを最大10分ほどキャッシュするため、公開直後は少し待つ
